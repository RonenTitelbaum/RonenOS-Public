# Bounded PBS workflow

1. State the requested outcome and choose the smallest useful checkpoint.
2. Read the necessary current public source once; retain its path and version.
3. Perform the authorized step with observed tools. If a prerequisite is absent,
   complete independent useful work and identify the exact dependent blocker.
4. Verify the result at the level claimed. A test pass is software evidence,
   not proof of live account facts, economic results or human outcomes.
5. Record the new state and next action. Keep failures and uncertainties visible.

Use a task fingerprint: objective, blocker, attempted action, observed result.
First unchanged repeat: change method. Second unchanged repeat: stop that loop
and report the blocker. A new user instruction or material evidence can reset it.

Keep raw evidence outside the short report. Report measured calls, bytes and
elapsed time only when observed; do not convert them to guessed token, energy
or money savings. A handoff is saved text, not proof another chat read it.
